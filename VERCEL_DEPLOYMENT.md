# Vercel deployment checklist — cartoony.site

The production blockers are addressed in code. **Apply the migrations before enabling the updated admin area.** No production database, Storage settings, DNS or deployment has been changed automatically.

## Exact Supabase setup (operator action)

1. Open the correct Supabase project → SQL Editor → New query. Confirm the original schema migration `202610240001_cartoony_schema.sql` and artwork migration `202610250001_movie_images_storage.sql` are already applied; do not replay seed data.
2. Paste the full contents of `supabase/migrations/202610250002_shared_admin_security.sql` and click Run. This creates private auth tables and four service-role-only RPCs, with RLS enabled and anon/authenticated access revoked. Keep `cartoony_private` out of the API's exposed schemas.
3. In a new query, paste `supabase/migrations/202610250003_private_image_staging.sql` and click Run. It configures `movie-image-staging` as PRIVATE and `movie-images` as PUBLIC. Both enforce 5,242,880 bytes and only `image/jpeg`, `image/png`, `image/webp`. Restrictive policies prevent visitor writes and staging reads even if other permissive policies exist. Do not add public write policies.
4. Confirm both buckets under Storage. No CORS allowlist change is normally needed on hosted Supabase; test a direct browser PUT in Preview, and allow the Preview/production origins at any custom proxy if applicable. Never make staging public to fix an upload error.
5. Keep the same six environment variables from `.env.example`, using the server-only secret/service-role key for RPCs and Storage. No new paid service or environment variable is required. Use separate projects/secrets for Preview where possible.
6. Sign in again: old stateless cookies have no registered session and are rejected. Missing migrations, RPC failure or database outages deny login/protected requests; there is no in-memory fallback. If PostgREST reports stale schema, run `notify pgrst, 'reload schema';` in SQL Editor.

## What changed

- The browser requests a signed upload URL with small JSON metadata after a shared admin-session check, then uploads image bytes directly to Supabase's private bucket. Vercel never receives the multipart/image body. Tickets are signed, expire after two hours, and are bound to the originating session, unique path, declared type and size. Signed URLs are bearer capabilities: never log/share them. A signed URL may still place bytes in PRIVATE staging after logout until it expires; revocation prevents finalization/publication.
- Finalization rechecks the session, reads at most 5 MB from private Storage, verifies byte signatures/type/actual size, fully decodes with `sharp`, rejects animation and excessive dimensions (25 megapixels / 10,000px per side), strips metadata including EXIF/GPS, and re-encodes before writing to the public bucket. The validated output must also fit 5 MB. Public objects use unique names and cannot be overwritten by browser capabilities. Existing previews, manual URL fields, movie saving and shared-image protection are retained.
- Login consumes an attempt atomically in PostgreSQL BEFORE password verification: five attempts per HMAC-hashed client IP per 15 minutes, shared across instances. Successful logins also count; no success reset can erase concurrent attempts. Vercel's trusted forwarding header supplies the IP; another reverse proxy must overwrite forwarded headers rather than trusting visitor-supplied values.
- Session token hashes are registered in PostgreSQL; signed cookies remain Secure/HttpOnly/SameSite=Lax in production. Every protected request checks shared expiry/revocation without caching. Logout commits shared revocation before clearing the cookie; if persistence fails, logout does not report success. Rotating `ADMIN_SESSION_SECRET` invalidates all cookies and upload tickets.
- Auth records expire; old records are pruned during login/session creation. Normal success, validation failure and explicit cancellation attempt staging cleanup. Browser crashes, revoked sessions or lost responses may leave private objects. Periodically delete staging objects older than 24 hours via Supabase Storage's UI/API (never SQL-delete `storage.objects` rows). Inspect movie/series references before removing any unused PUBLIC artwork.

## Vercel settings and launch checks

- Next.js preset, repository root, Node.js 24.x, build command `npm run build`, default output. Keep `pnpm-lock.yaml` and automatic pnpm detection; install optional native packages so `sharp` has its Linux binary. Never serve `out/` or use static export.
- Add `.env.example` variables in Production/Preview settings. Keep `.env.local` untracked. Public pages and sitemap stay dynamic with uncached database reads; publishing requires no redeployment. No video hosting is included.
- Run `node --test tests/production-blockers.test.cjs`, `npm run build` and `npx tsc --noEmit`. These regression tests use synthetic credentials and mocked external services: no production changes. PostgreSQL concurrency and hosted Storage policy enforcement still require validation after migration.
- In an isolated staging project, run `supabase/tests/shared_admin_security.sql` in SQL Editor (its test writes roll back). Test six parallel login attempts from the same IP across two application instances: only five reach credential verification. Log in on instance A, copy its cookie only within your test harness, log out on B, then confirm A rejects that cookie. Avoid logging cookie values.
- In Preview, upload real JPEG/PNG/WebP posters/backdrops, including an image between 4.5 and 5 MB; verify browser requests send bytes only to Supabase and only validated images become public. Reject >5 MB, empty, spoofed MIME, malformed files, unauthorized signing/finalization, and visitor direct bucket writes. Save/reload a test movie and exercise replacement/cancel. Do not test mutations against production without explicit approval.
- Later, only with approval, add `cartoony.site` in Vercel Domains, follow its supplied DNS records and verify HTTPS/cookie flags. No deployment or DNS changes were made here.
